1. Self-Introduction (1 min)
Hi, I'm Patrick. I've been a full-stack engineer for 10 years, currently working at a robotics AI company. I built a robot cloud management platform with Go and React — config management, GPU monitoring across three cloud vendors, the whole thing. Before that, I built Go microservices at TAL Education. I'm self-taught in AI — I went from watching 3Blue1Brown to building RAG pipelines with ChromaDB and DeepSeek. I'm looking to go deeper into AI Native products, especially Multi-Agent systems.
10年全栈 → 机器人AI公司 → Go+React云平台 → 好未来微服务 → 自学AI → 想做Multi-Agent
2. Why Multi-Agent? Why this company?
I think Multi-Agent is the next big leap. Single agents are great for simple tasks, but real work involves multiple specialized agents collaborating — planning, executing, reviewing. I built a basic version of this at my current job: one agent monitors GPU metrics, another pushes alerts, a third generates reports. Your company is building this as a product, which is exactly where I want to be.
Multi-Agent是下一步 → 我在现公司做过雏形：监控agent + 告警agent + 报表agent → 你们把这做成产品正是我想做的
3. Describe your robot cloud platform
We built a Go backend with Gin framework and a React frontend. The platform manages robot configurations across multiple robot models — firmware versions, SSH keys, deployment states. For GPU monitoring, we aggregated metrics from Alibaba Cloud, Baidu Cloud, and Volcano Cloud APIs. We used Feishu bots to push alerts when thresholds were breached. I owned the full stack — from database schema design to frontend deployment.
Go+Gin后端 + React前端 → 机器人配置管理 → 多云GPU监控聚合 → 飞书告警 → 全栈负责
4. How do you use AI Coding tools?
I use Claude Code and Codex daily. For new features, I describe the requirements and let AI scaffold the boilerplate, then I review and refine. For debugging, I paste error logs and stack traces — AI helps me trace root causes much faster. I also use AI to write tests and documentation. I'd say AI tools save me 30-40% of coding time, especially for repetitive tasks like CRUD endpoints and config files.
每天用Claude Code/Codex → 新功能用AI搭骨架 → 调试用AI分析日志 → 省30-40%时间
5. Agent Architecture — Memory & Context
I think of agent memory in three layers: short-term is the current conversation window, medium-term is Redis-backed session state with TTL, and long-term is a vector database storing summarized embeddings of past interactions. Context management is about deciding what to keep and what to compress. I use a sliding window for recent messages plus a running summary of older context, generated periodically.
三层记忆：短期(对话窗口) + 中期(Redis会话) + 长期(向量库摘要) → 上下文用滑动窗口+定期摘要
6. Production incident response
My approach: first, check the blast radius — which services, how many users affected. Then I pull up Grafana dashboards and trace logs to identify the bottleneck. I've dealt with API latency spikes before — at my current job, we had telemetry APIs spike from 200ms to 2 seconds. Turned out to be a gRPC connection leak. We patched it, added connection pooling limits, and set up alerts for the next time.
先看影响面 → Grafana+日志定位 → 经历：遥测API 200ms→2s, gRPC连接泄漏 → 修+加连接池限制+告警
7. Why should we hire you?
Three reasons. One: I've done 0-to-1 — I built a robot cloud platform from scratch, owning backend, frontend, and deployment. Two: I understand the full AI stack — not just calling APIs, but vector databases, RAG pipelines, agent orchestration. Three: I'm used to moving fast with AI tools. I can prototype an agent in a day and have it deployed by the end of the week. For a startup building a Multi-Agent product, that speed matters.
三个理由：① 0到1经验 ② 理解全AI技术栈 ③ AI工具加持下手快
